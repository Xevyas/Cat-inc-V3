# Cat Inc — Handoff Document

Living state doc for continuing work on this game in a fresh conversation. Not a changelog — keep this updated to reflect *current* state, not history. When something here goes stale, fix it in place rather than appending a correction.

## What this is

"Cat Inc" — vanilla JS incremental/idle browser game. No framework, no build step. Player recruits Cats, assigns them to production recipes, explores a map, trains jobs and builds houses.

## Critical rules (do not violate)

- **Work in `V3 - ChatGPT/` only for this optimization branch.** The original `V3/` copy is the owner's fallback and must not be modified.
- **Never auto-publish to GitHub.** Only commit + push when the user explicitly says "publie" / "publie sur github" / "publie le".
- **Cache-busting versioning**: every asset/script/style reference uses `?v=X.XXXX`. Bump by exactly **+0.0001** on every publish, across *all* occurrences (index.html, style.css, jeu.js — including image paths baked into JS string constants like `KITTY_ICON`, `CAT_FACES`, `LIVRE_ICONE`, `CHECK_ICON`). The publicly published version was **v0.0027** when this optimization branch was created; the current working references are listed under “Recent work”. One pre-existing straggler not on this scheme: `img/interface/Work_Final.png?v=2` (index.html, Work tab icon) — not part of the `0.00XX` convention, left alone.
- **Game release version**: the player-facing version is shown in Settings as `v0.0036`. This is separate from `SAVE_VERSION` and from technical cache-busting query strings. Increment it only in the same release commit that is explicitly published to GitHub; local edits must leave it unchanged.
  - **Release notes and changelog**: `js/data/changelog.js` is the single source of truth for the player-facing release history. Published entries in `releases` are immutable snapshots: never append later local work to the current published version. Every change made after publication goes into `pendingRelease`, whose `baseVersion` identifies the GitHub release it follows. Pending changes are not exposed by the launch panel or Settings. When publishing, promote the pending categories into a new newest `releases` entry, assign the new version and release date, clear `pendingRelease` for the next cycle, and bump the player-facing version in the same release commit only. The launch panel uses the newest published entry, while Settings renders the published history through **Changelog**. `releaseNotesSeenVersion` is persisted in the save; a new release opens the notes before the AFK summary, keeps Continue disabled for 5 seconds, then records the version only when the player closes the panel. Categories are `New Features`, `Balancing`, `Quality of Life`, `Bug Fixes` and `Other`; use `Other` for wording/clarity and discovery-state changes that are not new mechanics or balance. If a future change is ambiguous, confirm its category with the owner before publication.
  - Any time an image file is swapped or a new image constant is added, it needs a `?v=` matching the current release, or it'll get stuck in browser/GitHub Pages cache after future updates.
- **Never commit private or staging material**: `img/Backupo/`, `Perso - pas pour github/`, `img/CHATGPT Instructions/`, `img/To be converted/`. `.gitignore` protects them and also keeps currently unused future art local, but publication must still stage explicit files rather than `git add -A` / `git add .`.
- **Game is 100% English.** Always translate French feature names/labels before implementing. Confirm if a translation is non-obvious. (Note: `NOMS_KITTIES` in jeu.js still has one French name "Cléopatra" — pre-existing, not yet flagged for fix.)
- **Story punctuation**: never use em dashes in story copy. Orange narration lines use plain text without surrounding punctuation; dialogue must use commas, periods, colons or a natural rewrite instead.
- **Story character voices**: `Documentation/story_dialogue_guide.md` is the source of truth for story tone. - **Development mode**: normal URLs hide the speed selector and forced Bird button and keep the game at 1×. Add `?debug=1` to expose the full 1×–1000× selector and Bird test button. The flag is URL-only and must never be stored in saves. See `Documentation/DEVELOPMENT_MODE.md`.

- **Jobs and Engineers reference**: `Documentation/jobs_and_engineers.md` is the consolidated catalog of normal jobs, manager families, sphere perks, Bernardo/Explorator perks and engineer ranks. Keep it aligned with `METIERS`, `JOB_CENTER_JOB_INFO`, `SPHERE_GRIDS` and `ENGINEER_RANKS` whenever those definitions change.
- **Mini-game runtime**: every current and future mini-game must use the shared foreground lifecycle documented in `Documentation/mini_games.md`. Never create an unmanaged `requestAnimationFrame` loop or keep the 100 ms background UI render active behind a mini-game. Animated controls use transform-based movement, a capped frame delta and suspension-safe clock resets; static mini-games still enter the same singleton session.

## Resource tier framework (established, keep using this)

- **Tier 1** = the first/cheapest resource pair in time and materials.
- **Simple resource** = private intermediate gathered inside one recipe slot (left side, e.g. Cardboard Pieces). It never enters the shared inventory and has no global quantity. It stays with the slot when its Cat is removed or replaced, and is discarded only when the recipe is changed or cleared.
- **Finished resource** = globally stored output produced after the slot completes Gathering and Processing (right side, e.g. Cardboard Planks).
- **Cost tier badges**: building cost rows display the same color-coded `T1`/`T2` tier pills used by Work and the top resource rail. Keep adding the matching badge whenever a new building cost resource is introduced.
- **Map fog layering and motion**: one map-wide SVG mask covers every unrevealed cell and cuts the fog out over Home and explored zones. Its white base rectangle and every black revealed-zone cutout must keep `shape-rendering="crispEdges"`; normal SVG anti-aliasing exposes faint cell-boundary grid lines at fractional mobile widths. Inside it, a main original + mirrored + original texture strip moves right over 90 seconds, while a vertically offset second strip moves in the same direction over 140 seconds at 25% opacity. Their different speeds create visible cloud depth without changing gameplay visibility. A very light horizontal SVG blur flattens raster sampling at the joins, so neither zone boundaries nor either animation loop produce a visible line. Both phases are locked to a shared clock, so selecting a zone and rebuilding the map DOM does not visibly reset or stop the drift. Locked/explorable zones are not desaturated or outlined under the fog, and the `?`, lock and mission badges stay above the global layer. The first zone-exploration assignment slot is aligned with the other slots and only accepts an Explorator or Bernardo with `EXPLO`. `prefers-reduced-motion` keeps both strips static. For an immediate rollback, set `MAP_FOG_MOTION_ENABLED` to `false` in `jeu.js`.
- **Map artwork seams**: when a region supplies `mapImg`, `renduCarteGrille()` renders one `.carte-map-artwork` layer behind transparent clickable zone cells. Do not restore per-cell background-image slices: fractional `--map-cell` widths on mobile create visible hairline grid seams. Bump the `jeu.js` cache-buster in `index.html` whenever this renderer changes so clients cannot keep the sliced version.
- **Auto-feed XP**: Gang's Auto-feed to next level uses a bounded XP-combination search and minimizes overshoot before minimizing food units. If the selected food plan exceeds the exact XP need, it opens the in-game confirmation modal unless the persisted Settings toggle `avertirSurplusNourriture` is disabled.
- **Recipe rule**: each current family recipe requires **10 private units of its paired simple resource**, or 8/6 with the qualified processing manager's `REDUCED COST I/II` perks. New multi-finished-resource recipes belong to the future scientist/engineer laboratory system, not this Work flow.
- **Study assignment rule**: Bernardo is the Cat who studies books. While `learningEnCours` is active, he is treated as busy and cannot be assigned to Work, campaigns, scoutings or zone explorations until the study completes.

## Architecture / key concepts

- **`CONFIG`** (top of jeu.js) — central game balance: unlock thresholds, timing per action (`secondesParUnite`, `secondesParPlanche`, etc).
- **`RESOURCE_PAIRS`** is the Work source of truth and drives mechanics, recipe choices and generated cards. Each entry declares `recipeId`, family, tier, private simple input, finished output, timings and manager families. `initialiserWorkStructure()` generates two base recipe slots per family, then adds one slot for each learned manager `NEW SLOT` perk mapped to that family; higher tiers are sorted first in the recipe picker.
- **Work tab layout**: Work is family-first with `Wood`, `Food` and `Rocks`. Each visible family starts with two recipe cards and can gain more through manager `NEW SLOT` perks. A card shows the private Gathering input on the left, its single assigned Cat in the centre, and the globally stored output with projected rate on the right. With a Cat assigned, Gathering shows the total time to fill its private input plus the per-unit interval; Processing shows its transformation percentage and the adjusted Processing duration for the output quantity. Beneath the Cat name, the card displays both the full recipe net production per minute and `Cycle: ...`, calculated from the complete adjusted Gathering + Processing duration. The whole Gathering card background fills from bottom to top during Gathering and stays full during Processing; the Processing card background then fills during Processing. Resource icons remain fully visible and static. The Cat ring combines both halves, so one full rotation equals one complete recipe. The redundant lower phase/status band is intentionally omitted. Empty slots keep the same padded slot-title header and use a borderless full-card selection button. Cards sit side by side on wide desktop and stack on narrower layouts; their internal three-node flow remains visible on mobile. From four Cats onward, the currently active phase card is also the Manual Focus control; its separate `?` button preserves access to production details.
- **Resource tiers in compact UI**: Selected Work recipe headers and the `All` summary rows show compact color-coded `T1`/`T2` badges before their output icons, and the top Resources rail shows the same color-coded tier badge to the left of tiered processed-resource icons; values and unlock visibility remain unchanged.
- **Work `All` summary**: `All` is the default Work view and renders one compact card per unlocked family. Its header reports occupied capacity as `active slots / available slots ACTIVE` (for example `1/2 ACTIVE`); the denominator is read from the family's actual slot array and is part of the render key, so future slot unlocks update immediately. Each active slot is a separate clickable row with the finished-resource icon/name, assigned Cat portrait/name and level, full-cycle projected output per minute and the same `progressionsSlotRecette(...).overall` ring used by the detailed recipe card. It intentionally exposes no Gathering/Processing phase detail. Clicking a row opens and highlights its detailed family slot; configured recipes without a Cat are counted in a separate action that opens the first waiting Cat picker. Once the Job Center is built, each family header identifies its `Gathering Manager` and `Processing Manager` by name only; manager bonuses remain out of this compact view because each manager may eventually grant several effects. Wide layouts show three family cards; narrow and mobile layouts stack them.
- If a Work family has no active production in the `All` summary, its card also offers a compact `Go to Wood`, `Go to Food` or `Go to Rocks` action that switches directly to that family sub-tab.
- **Recipe slot sizing**: empty recipe slots reserve the same header and flow heights as populated slots, so neighbouring cards remain aligned whether a recipe is selected or not. The `+ Choose a recipe` control fills the reserved flow area and centers its button at the same vertical position as the `Assign a Cat` control; mobile uses matching compact dimensions.
- **Compact Work family headers**: the `Production family` kicker and family name remain at their existing font sizes, but the explanatory sentence is intentionally omitted and the header uses minimal vertical padding. This keeps each family band compact while preserving the manager rail when the Job Center is built.
- **Recipe cycle**: `tickWorkRecipes()` calls the shared `avancerRecetteSlot()` engine for active and offline progress. The assigned Cat gathers its own private input, then processes it and loops. `1.05^level` affects Gathering (+5% per level); `1.03^level` affects output quantity (+3% per level) and persists fractionally in `outputCarry`. Every unlocked slot may run the same recipe independently.
- **Offline progression**: `appliquerProgressionHorsLigne()` centralises AFK balance with `VITESSE_HORS_LIGNE = 0.10`, a 60-second minimum gap and `MAX_AFK_SECONDS = 10h`. The capped simulated time advances Work, catch/recruit cooldowns, campaigns, zone explorations, scoutings, Study/Learn and Job Center training. Catch/recruit remains a player-triggered action and never grants a cat automatically while away. Active mission power/success rates stay frozen from launch; completed results remain pending for the normal claim/reveal flow. Mobile resume handling persists before `visibilitychange`, `pagehide` and `freeze`, then retries catch-up on `visibilitychange`, `pageshow` and `focus` so suspended/bfcache tabs do not miss AFK processing. `afficherResumeAbsence()` uses real resource sprites and existing interface artwork for every summary row; do not reintroduce emoji labels there.
- **Camp Engineers**: after studying `The Engineer's Path` and building the Laboratory, the Laboratory trains passive `Camp Engineer` jobs through a Job Center-style cat-selection modal. The first Camp Engineer is Rank 1 and adds 6 minutes to the AFK cap per cat level. After `The Teamwork Advantage` is learned, a second Camp Engineer can be trained as Rank 2; it does not inherit Rank 1's effect and instead adds 0.5 percentage point to the AFK ratio per cat level, capped at the global Cat level 100. Durations are 2h, 4h, 8h, 12h, 16h, 20h then 24h (the final cap). Engineers are omitted from Work, manager and Exploration assignment modals, and their Experience panel shows only their rank-specific passive AFK bonus. Gang subtabs (`All`, `Managers`, `Engineers`, `Stray Cats`) appear after the first Engineer is trained. All Cats, including engineers, share the level cap of 100.
- **Recipe selection flow**: choosing a recipe in a slot with no Cat automatically opens that slot's Cat picker after the recipe modal closes. Changing a recipe in an already assigned slot keeps the existing flow and does not open a second picker.
- **Work confirmations**: changing or clearing an occupied recipe slot uses the in-game `#work-confirm-modal` instead of the browser's native `confirm()` dialog. Before confirmation, the recipe picker is temporarily hidden so only one `aria-modal` dialog and one tap-capturing overlay remain active; Cancel, Escape and the overlay reopen the unchanged recipe picker, while continuing applies the existing discard rule. The confirmation has an explicit higher stacking level as an additional mobile-browser safeguard.
- **Recipe banner interaction**: the complete selected-recipe banner is a native button, not only its visible `Change` label. Its children ignore pointer events so tapping the icon, recipe name or Change text always opens the same picker; clicking the assigned Cat portrait opens that same picker to replace the Cat, while the separate red cross removes it. Recipe choices and the 44px Clear action use `touch-action: manipulation` for reliable mobile input.
- **Work wording**: player-facing copy calls the basic-resource phase `Gathering` and the finished-resource phase `Processing`; bonus labels use `Gather Production Bonus` and `Process Production Bonus`. The slot-local behavior remains unchanged.
- **Work resource details**: the `?` button in the corner of each Gathering or Processing panel opens the shared `#inv-res-popup` with that slot's active bonuses. Gathering shows raw/adjusted time for one and for the effective input target (10, 8 or 6 with `REDUCED COST I/II`); Processing shows the raw/adjusted cycle and worker yield per cycle. The popup deliberately does not show a per-minute output because that would omit the recipe's Gathering time; the complete rate remains on the recipe card. Inventory resource cards intentionally keep their generic information popup because they have no slot worker context.
- **Manual Focus**: recruiting the fourth Cat unlocks the one-time `A Little Encouragement` story and Manual Focus. Each click or tap on the currently active Gathering or Processing panel adds 0.8 seconds to a reserve tied to that recipe slot, capped at 30 seconds, and applies a transient `×2` speed multiplier across both phases of that recipe. The remaining reserve automatically follows Gathering into Processing and Processing into the next Gathering cycle while continuing to drain, including while another game tab is displayed; further clicks on the active phase refill it. Clicking the active phase of another recipe abandons the previous reserve and starts the new slot with only that click's 0.8 seconds. The active recipe card adjusts both phase durations, the full cycle time and projected production per minute, and the top resource rail uses the same adjusted cycle. The compact gauge follows the active phase and shows the remaining charge, its 30-second capacity, a `MAX` state and an orange low-charge state without increasing card height. Removing/replacing a Cat, changing/clearing a recipe or using `Unassign all Cats` clears the reserve. Manual Focus is never saved and is excluded from AFK simulation.
- **Stable interaction rendering**: the master `rendu()` dispatcher is temporarily deferred from `pointerdown` until the browser resolves the corresponding `click` on interactive controls, with a 120ms fallback after a cancelled interaction. Simulation and timers keep advancing at their full effective speed, but structural DOM renders are coalesced into one catch-up render after the click or hold completes. Click handlers may render synchronously once their original target is secured. This prevents ×100/×1000 developer simulation, and future player-facing time acceleration, from replacing controls between press and click. Keep future time boosts in simulation multipliers rather than increasing DOM render frequency.
- **Rendering/performance split**: `tick()` stays at 100 ms for gameplay timing, while `renduDynamique()` updates timers, quantities and progress in place. `rendu()` is reserved for structural changes and dirty sections. Main tab visibility changes paint first and schedule one coalesced structural render on the next animation frame; Gang still calls `renduManagement()` from that deferred callback. Mini-games continue using the shared foreground runtime and suppress both background render paths while active. See `Documentation/rendering_and_performance.md` before adding a recurring timer, animation or new screen.
- **Sphere connector layering**: SVG connectors are emitted before perk nodes, and locked nodes keep an opaque grey circle. Do not lower the whole locked-node group opacity, because that makes the dotted connector underneath visible through the circle.
- **Sphere state precedence**: every grid's central perk is `learned` with the job and must never be downgraded. `sphereEtatEffectif()` gives this default learned state precedence over stale saved values, repairing affected saves at render time. Learning a perk unlocks a connected child only when that child's effective state is actually `locked`; it must not write `unlocked` over a default `learned` or already accessible node.
- **Basic Stone Cathouse cost**: its first house costs 5 Basic Wood Planks and 5 Pebble Bricks. Both components use the existing `ceil(base × 1.7^n)` growth formula with a base of 5.
- **Work resource popup lifecycle**: structural slot cards may rerender after a state change, but an open Work production popup must remain visible across those rerenders. Dynamic Work progress updates should never replace the card DOM. Do not close the popup from `renduSlotRecette()` merely because the card DOM is refreshed.
- **Book Study assignment**: Study always assigns Bernardo as the learner and persists his `kittyIndex` in `learningEnCours`. If he is working in a recipe slot or as a manager, the player must confirm reallocating him first; active or staged exploration missions cannot be interrupted for Study. The Inventory study bar uses Bernardo's portrait as a moving marker, matching the recruitment progress bar.
- **Recipe Cat replacement**: removing, replacing or force-moving a Cat keeps the selected recipe's `gatheredInputs`, phase progress and `outputCarry` in the slot, so another Cat can resume the same cycle. Only changing or clearing the recipe discards that progress and private input; changing/clearing an occupied slot still asks for confirmation. The selected recipe remains when only its Cat is removed.
- **Work manager visibility**: the two family manager cards appear immediately when `etat.jobCenterConstruit` becomes true, not when the first specialist finishes training. Gathering managers affect every Gathering phase in their family; processing managers affect every Processing phase. `REDUCED COST I/II` changes only the private target from 10 to 8 or 6; `SPEED BOOST I/II` adds 25% per level to processing manager speed.
- **Work navigation**: `.work-filtres-btns` is the only Work sub-navigation and contains `All`, `Wood`, `Food` and `Rocks`. On mobile, `.work-subnav` stays in the shared fixed 48px rail immediately above the main navigation; the redundant `Production family` heading is hidden in the selected family views, and `Unassign all Cats` appears only in `All`. `changerOnglet(id)` synchronizes `document.body.dataset.ongletActif` for tab-specific responsive behavior.
- **Facilities navigation**: once the Training Center is unlocked, mobile Facilities uses the shared fixed sub-navigation rail with `Jobs` and `Train`. Learning the Engineer's Path and unlocking the Laboratory adds `Lab`. Only the selected facility panel is rendered in the mobile flow; desktop keeps the multi-panel Facilities layout. The Training Center no longer has a separate `Enter` step: once built, its building summary and specialization workspace are displayed together. Desktop keeps the inline job roster beside the sphere, while mobile replaces that long roster with one compact selected-Cat button that opens the shared Job Center modal in `spec` mode.
- **Exploration assignment alignment**: `.explo-slots` aligns its children to `flex-start`. The required first slot keeps the separate `EXPLORATOR` label beneath its card without stretching adjacent assignment cards to the wrapper's combined card-and-label height.
- **Responsive multi-resource costs**: building and Facility purchase buttons with more than one material use `.btn-achat-cout-multiple`. Every material is wrapped in an indivisible `.cout-groupe`, while the `+` stays with the following material through `.cout-groupe-suite`; mobile may therefore wrap the cost onto two clean lines without splitting a quantity, Tier badge or icon.
- **Gang allocation refresh**: Gang is rendered outside the master tab dispatcher, so `changerOnglet("gang")` must call `renduManagement()` after switching tabs. This keeps each Cat's `Producing: …`, manager or free status current after assignments made in Work.
- **Save era**: schema version 2 deliberately ends compatibility with former independent `workers`. Current state contains only `workRecipeSlots`, with at least two independent slots for each `wood`, `food` and `rock` family; learned `NEW SLOT` perks append additional persistent slots. A slot persists `{ recipeId, kittyIndex, phase, phaseProgress, outputCarry, gatheredInputs, reservedInputs }`. Recognizable version 0/1 saves remain untouched and autosave is locked behind `#save-upgrade-modal`; restart preserves sound volumes and the adjusted-recruit-time preference. Do not add a migration from legacy workers because this update is intentionally restart-only.
- **Resource displays**: only finished resources appear in the top bar and have shared quantities/rates. Inventory retains simple-resource icons for discovery/reference but intentionally shows no number; their tooltip explains that they exist only inside recipe slots. `tauxProductionTransformee()` projects the full Gathering + Processing cycle and `afficherTauxNet()` renders finished output rates consistently. The rail is split between fixed controls (`Bird`, Cats), the scrollable `#ressources-liste`, and the fixed Manage action. Desktop uses a 70px rail with 42px icons; each quantity and projected rate sits in one compact line below its icon. Mobile retains its dense two-row presentation. Family changes never add separators in the rail; ordering and Tier badges provide the necessary context. `RESOURCE_BAR_ITEMS` is the single presentation registry for configurable resources; add every future top-bar resource there as well as in the markup.
- **`kittyAllocationLabel(kittyIdx)`** reports `Producing: <finished resource>` for a recipe Cat and is shared by Gang and assignment modals.
- **Force-reassignment pattern**: `.btn-forcer` calls `retirerKittyDeSesRoles(kittyIdx)` then `forcerWorkerRecette`, `forcerManager`, `forcerKittySlot` or `forcerKittyFormation`. Moving a recipe Cat preserves the destination slot's recipe cycle and leaves the source slot ready to resume when another Cat is assigned. Expedition/zone/scouting/training assignments remain non-interruptible.
- **Busy-state checks**: any modal that lets you assign a kitty must check the *full* set: `kittyIsOnExpedition`, `kittyIsOnZoneExplo`, `kittyIsOnScouting`/staging, `kittyIsInWorkerSlot`, `kittyIsInTraining`, `kittyEstManager`. Missing any of these was a recurring bug source — always copy the check set from `renduModalExplo` when adding a new assignment surface.
- **Kitty-picker sort order**: `renduModalExplo`'s list sorts by `metier === "explorator"` first, then by `niveau` descending (Exploration Power) — was missing the niveau tiebreak (fixed this session), which left high-EP kitties buried at the bottom in original catch order. `renduModalWorker`'s list already sorted by level descending; keep any new kitty-picker consistent with that (best/most useful kitty first).
- **`.ressource-taux`** (top bar production-rate text) stays on one compact line with an `8ch` maximum. Resource cards have fixed compact widths in the mobile two-row grid, so changing rate digits cannot resize neighbouring columns.
- **`formaterTemps(sec)`** — shared time formatter, dynamically shows Year/Day/Hour/Minute/Second, omitting larger units when zero.
- **Per-kitty face icons** (added this session): `CAT_FACES` maps face images in `img/Cat faces/`. `assignerVisageChaton(nom)` — Bernardo/Mochi/Luna always get their fixed face; every other recruited kitty gets a random face from the pool (excluding Bernardo's). Stored per-kitty as `kitty.visage` at normal catch/recruit creation and save-migration backfill. The first-three-cat Catch mini-game also reads these fixed portraits dynamically. Rendered via `kittyIconHtml(kitty)`. Generic/non-kitty-specific icon slots (slot counters, modal titles, multi-name lists) still use the old generic `KITTY_ICON` constant (`img/interface/Gang_Final.png`) — that's intentional, not a gap.
- **Passive Catch/Recruit cycle**: the player no longer starts a countdown that automatically grants a cat. `sequenceEnCours` now means the saved passive cooldown is still charging; `false` means the current action is ready. On a fresh game, closing the introduction starts Bernardo's original 5-second cooldown; only after it fills does his Catch action become available. `Start over` immediately reopens that introduction without requiring a page reload, leaving Bernardo's timer stopped until the player closes it. Success increments `clicCount` and begins the next cat's duration; failure begins the same current cat's duration without incrementing it. Cooldowns use the existing `dureeBrute()` and `vitesseAttrapage()` formulas, continue through reload/offline time, and stop in the ready state without ever granting a cat automatically. `actualiserProgressionSequence()` stores raw time already consumed plus the speed active for the last segment, so a newly built house, manager or other speed bonus accelerates only the remaining raw time and never retroactively reprocesses the elapsed portion. The green cooldown bar is always visible and carries a 30px circular portrait marker at its leading edge; once ready it remains filled at 100% with the portrait at the far right, alongside `Catch the Cat` or `Recruit the Cat`. `prochainVisageChaton` persists that exact upcoming portrait and the same value is assigned to the cat on success, so later random portraits cannot change across renders or differ from the recruited cat. The first three cats open the shared timing mini-game with their fixed portraits and cursor speeds Bernardo 60, Mochi 80, Luna 100; the 20%-wide target accepts one attempt, and a miss, overlay click, Give up, or Escape all restart the current cooldown.
- The recruiting-time `?` popup keeps the raw time first, then explicitly shows the base rate as `Base time per second · 1s/s`, followed by Wood House, Stone House, Gang Leader and total modifiers. This base line is informational only and does not change the recruiting formulas.
- **Purrsuasion Recruit mini-game**: from the fourth cat onward, `Recruit the Cat` opens a mouse/touch/keyboard hold-and-release trust game. The 10-second clock and cursor movement remain paused until the player's first press on `HOLD TO START YOUR PITCH`. Trust starts at 18; holding raises it at 42 points/s and releasing lowers it at 20 points/s, both multiplied by difficulty speed. Chat 4 starts at Difficulty 1 / ×1.00, and each successfully recruited cat adds one difficulty level and +10% cursor speed (`difficulty = etat.chatons - 2`, multiplier `1 + (difficulty - 1) × 0.1`), displayed at the top of the modal. The player must accumulate 2 seconds inside the 42–68 `INTERESTED` zone; touching 68 and entering `TOO PUSHY` fails immediately. Timing out, Give up, overlay click, or Escape also fails. Opening the modal no longer starts any cooldown behind it: only the result does so, with failure restarting the missed cat's cooldown and success calling `terminerSequence()` to start the next cat's cooldown. The pitch button and mini-game card disable native text selection, including WebKit touch-callout selection, so long-pressing on phones never highlights the `HOLD TO START YOUR PITCH` label.
- **Recruitment handoff story**: after `The adventure begins`, the first completion opens a small `A new way to get more cats` popup explaining that Bernardo is taking matters into his own paws and recruiting new cats. The handoff is recorded in `storiesVues` as `story3TransitionVue`, so replaying the story from Logs does not reopen the popup.
- **Purrsuasion dialogue pool**: every attempt selects one of ten paired visitor/Bernardo exchanges in `RECRUIT_DIALOGUES`, with an offset reroll preventing an immediate repeat. - Gathering managers have `PROD BOOST I/II` and `SPEED BOOST I/II` perks. Each level adds 25%, so level II brings the corresponding total to 50%; level I costs 1 Canned Cat Food and level II costs 2. Production perks affect Gathering quantity, while speed perks affect the manager's speed bonus. Processed families remain unaffected.
- Carpenter, Chef and Stonemason each have a six-node complex sphere: `REDUCED COST I/II`, learned `PROD SPEED` center, `SPEED BOOST I/II` and `NEW SLOT`. Level I perks cost 1 Canned Cat Food, level II perks cost 2 and require their level I predecessor. Cost levels change the Gathering target from 10 to 8 or 6; speed levels add 25% each to processing manager speed for `sawmill`, `catchen` and `pawsonry`.
- Wood Builder has a fifteen-node sphere around learned `PROD SPEED`. `AUTO BUILD` leads to `PERFECT BUILD I/II`; automatic houses still use their theoretical cost for the below-50%-of-stock eligibility rule, but the matching Perfect level prevents material consumption. Manual builds always consume materials. The left branch contains `EXPO REDUCED I/II/III` (`1.6`, `1.55`, `1.5`), `COST REDUCED I/II` (`×0.5`, then `×0.25`, rounded up) and `BOX BOOST` (`1 + 0.05 × boxCount` on Wood Cathouse speed). The right branch contains `GLOBAL SPEED I/II/III` (+25% per level), `BOX SPEED` (base Cardboard Box speed ×3) and `WOOD SPEED` (base Wood Cathouse speed ×2). Legacy `builder-cost` and `builder-speed` ids map only to `EXPO REDUCED I` and `GLOBAL SPEED I`.

## Conventions to follow when adding new features

- **Garden campaigns**: B1 and F1 each have a `Search the garden` campaign (difficulty 15, 20 minutes, 2 slots, 10 Human Leftovers) and intentionally have no scouting mission.
- **Parking campaigns**: `parkingLeft` and `parkingRight` each have a `Search the parking` campaign (difficulty 35, 40 minutes, 2 slots) and intentionally have no scouting mission. The left parking rewards 2 Rock Bricks; the right rewards 1 Rock Brick and 5 Basic Wood Planks.
- New boolean settings → follow the `.settings-toggle-row` pattern already in the Settings modal.
- New family Work recipes → add one `RESOURCE_PAIRS` entry with its paired private simple input, finished output, timings and manager families. Do not route multi-finished-resource recipes through this system; those belong to the future laboratory flow.
- New kitty-specific UI → use `kittyIconHtml(kitty)`, not the raw `KITTY_ICON` constant.
- New assignable-kitty modals → copy the full busy-state check set (see "Busy-state checks" above).
- Any new image asset → add `?v=<current version>` from the start.
